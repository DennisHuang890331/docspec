# roadmap 錯誤連結的合法恢復

日期：2026/10/04。狀態：同題實測新發現，方案待負責人裁定；尚未改程式、完成算法或案例 wheel。

## 問題與實據

Windows 原實作者把 `RL-gpt-11` 裸編號加入 W-gpt-1；正確引用是 `gov:RL-gpt-11`。這是 agent 的輸入錯誤，與工具問題分開記錄。`roadmap link` 接受非法命名空間並返回成功；補加正確引用後，原錯誤仍在。`check` 將其列為結構錯誤，文件 freeze 的真實 dry-run 為 NO-GO。現行 roadmap 只有新增連結，沒有合法刪除或更正入口；不能要求使用者破壞封條、刪工作或豁免來繞過。

root 使用相同已安裝 wheel 在全新合成專案重現：初始 check ok=true，加入裸引用後 ok=false，補正確連結後仍 false，`roadmap unlink` 返回 2，工作檔位元組未改。十次真實 console 命令、退出碼及輸出保存於案外 `independent-roadmap-link-recovery/repro-f6307188257641bea87ea194c4691799/`。此重現沒有修改原考場案例。

## 建議最小修法

1. `roadmap add`／`link` 在寫入前檢查明確提供的引用格式：只接受 `change:`、`doc:`、`gov:`、`swc:` 且冒號後非空。一筆非法就整次拒絕，不留下部分新增。沒有引用的普通工作仍可建立；不新增根據文字猜來源的行為。
2. 新增 `artispec roadmap unlink <工作編號> --ref <原引用>`，只移除明確指定的完全相同引用，保留其他引用、順序、工作編號及欄位。允許指定非法舊值，才能修復已存在的錯誤。引用不存在時為明確無變更，不改檔；工作不存在或封條損壞仍報錯。
3. 由原作者執行 unlink 移除錯字，保留正確引用、原 checkpoint、Q-gpt-2、失敗紀錄及更正理由；不改歷史封條。之後沿用既有 check／freeze／任務／證據判定，不把斷連當作任務完成，也不新增文件與軟體的完成閘門。

不自動修正使用者的引用，不新增紀錄種類、必填表單、多人編輯或產品並行寫入。本案不提議將治理結構錯誤降成提醒；缺失來源仍不能顯示完成。
