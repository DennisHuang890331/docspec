## 2. 重跑時維持的契約

沿用 `scripts/validation/build_exam_workflow_cases.py` 的合成任務、負責人回答範圍、students.csv、一次變更及接手指示，保存每項內容指紋。規模仍為兩班 16 人、兩間各 4×4 座位；功能仍是 CSV 匯入、排座及座位表，一份短操作手冊與實際輸出示意圖。

只注入原本的容量／剩餘座位變更一次，並在第二次工作未完成時交由無前文的新會話接手。文件與軟體在同一專案內進行，測試角色獨立撰寫／簽收，實作者不能改測試；文件依原合成授權定版，軟體由引擎取得實際證據與當前接受後封存。

ArtiSpec 使用者的工程團隊定位不改變這個合成任務的教師讀者。新工具預設應按既有任務調整手冊，而不是換題目、讀者或增加功能來顯示改善。

Windows 與實際 WSL Linux runtime 各建全新隔離案，使用同一新 wheel。產品與自動測試分平台記錄；實際 Windows GUI／Explorer 操作按原交付限制驗證。前次未測乾淨無 Python 主機與整機實體斷網，這次也不能自行擴充契約或用其他範圍冒充。

## 3. 開始前與執行中

先核定待採用的設計、完成相應正反案例與回歸，再固定 wheel、任務與評分版本。保留原兩案與原始失敗；新案、事實清單、評分資料、前後指紋與完整啟動參數放在 repo 外。參與者只取得同一任務及公開指南，不取得答案。

記錄實際模型／會話識別、平台、runtime、套件、排版工具及指令入口。已安裝 CLI 的 args、cwd、退出碼、stdout／stderr 原樣保存，外層紀錄器與真正程序的退出碼分清。shell history 未取得就列缺漏，不以自報補齊。

作者停止修改後再取完整交付包並核對 manifest。獨立審查針對同一完成包、有效證據、簽收與文件版本評分；查核角色不把額外命令混入參與者統計，不改測試答案或把失敗回填成成功。

## 4. 比較的差異

- **流程正確性**：背景來源是否誤阻完成、preview 是否查到本次草稿、必要簽收與當前證據是否仍被要求。
- **兩域同時工作**：未封存需求的來源是否清楚，文件是否避免為引用而推動軟體提早封存，兩域是否保留各自完成條件。
- **接手品質**：有效決策、原引用、最新失敗、測試簽收、未定版內容與下一步是否辨識完整，是否沿用工作再重寫交接。
- **文件可用性**：操作步驟與成功判斷是否有據，限制是否保留，治理／驗收流水帳是否打斷使用說明，圖、PDF 與 proof 是否對應同版實際產物。
- **資訊成本**：依紀錄統計查詢、help、失敗與重試、來源跳轉、摘要 bytes；相同分類口徑才比較，缺少的歷史資料列無法比較。

比較報告逐項列原結果、新結果及來源，分開產品／流程缺陷、環境或控制器失敗、agent 表現。前次與這次若模型或執行條件不同，清楚列出；單輪前後觀察不宣稱嚴格因果或固定比例的用量改善。
