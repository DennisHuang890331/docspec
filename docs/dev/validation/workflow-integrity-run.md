## 1. 修改前先證明缺陷

`tests/test_workflow_integrity.py` 的前十個測試先在尚未修復的生產程式執行：**10 failed，7.03 秒**。命令及 fixture 均成功，失敗點分別是：

1. T2 有必要情境及計畫，沒連到實作任務、沒執行，封存仍成功。
2. 最新零收集執行失敗，任務仍沿用舊成功。
3. THEN 修改後仍沿用舊證據。
4. 同檔換測試位置、原簽收移除後仍完成。
5. 豁免裁定被駁回後仍算完成含豁免。
6. 程式改成 B、agent 補 inspection，仍用 A 的使用者驗收封存。
7. 提案階段不能先建立尚無測試計畫的測試型任務。
8. roadmap 手動結案覆蓋仍未完成的連結。
9. 決策依據裁定被駁回，相關軟體封存仍放行。
10. 文件舊版已定版，新增未定版內容仍顯示交付完成。

這些是正常指令會觸發的流程問題；未將冒充身分、刻意改測試環境等已接受風險納入修復。

## 2. 修復與規格對照

### 軟體證據（5 項需求）

- `software/scope.py` 保存版本、局部契約及指紋；`evidence.py` 比對目前範圍、檔案與簽收，先選最新嘗試再判是否有效。測試涵蓋 THEN、位置、covers、略過政策、無關需求／標題、同檔其他測試，以及舊格式補簽、補驗證。
- `tasks.py` 與 `archive.py` 檢查必要情境 → 規劃測試 → 實作任務 → 有效證據／豁免。測試涵蓋未執行 T2、規範句變更、共享測試單次執行、inspection／imported-done 不冒充測試、verified-by 只列真通過。
- 先成功後零收集／部分收集／逾時／無報告／找不到執行器，最後重新成功，均有 CLI 回歸。混合「某方法過時、另一方法最新失敗」保留兩個原因。
- 已封存紀錄只新增外部影響標記，不重開或改寫任務、證據。原封存交易回復、簽收保護與匯入測試仍保留。
- Windows 絕對／相對／UNC 路徑與 POSIX 引號、跳脫分開驗證；另建立含空白目錄的真實 Python 執行器，帶環境變數實跑測試並檢查 JUnit 證據。

### 裁定與驗收（4 項需求）

- 共用 `governance.invalid_basis`、`ruling_effective_status` 判斷。豁免引用仍有效且範圍相符才放行；駁回、取代、範圍改變及改用正常新證據皆有測試。
- `impact.py` 沿既有連結傳遞，含巢狀能力名稱；`software/links.py` 保留封存歷史可追溯。封存另直接驗依據，不能靠清 suspect 恢復失效授權；無關 change 保持可封存。
- 使用者驗收保存相關需求的全部實作範圍及宣告檔案；改另一個同需求任務也會過時。只有程式變更、沒有規格 delta，仍檢查需求方法與目前版本的使用者驗收。
- `test_software_errors_do_not_hold_up_documents` 以實際文件定版驗證領域獨立，並確認單獨 stale-software 不使已定版文件工作退回未完成。

### roadmap（3 項需求）

- 手動 done 限無完成參照、無子項目的小工作，純決策約束仍可結案。舊 closed 後新增連結／子項目改依現況推導。
- 整份文件比對目前工作內容與定版快照；章節寫好與整份文件交付分開。
- 文字及 JSON 共用 details，包含前置工作、失敗證據、待規劃／待驗收、未定版及子項目原因；測試比較完整原因字串與讀前後紀錄位元組。

### 工作流程與交接（4 項需求）

- 草案先建 verify=test 任務，交測試角色規劃／連結／簽收，再執行證據的完整 CLI 流程可走通；沒有虛構 id 或改驗證方法。
- 產生的中英文 AGENTS 區塊及六個工作 skills 要求先查 roadmap、同範圍沿用、缺少才新增並保存回傳 id；保持區塊外規則。覆述只在不清楚時，資訊與裁定分開，移除過時 govern 及並行受管紀錄寫入指示。
- handover 以內容指紋及帶時區時間判新鮮度。同日裁定、證據、文件文字／圖來源變動會過時；mtime、單純讀取不會。重寫恢復 current；舊單、損壞治理或文章紀錄、不可讀檔案回 unknown 並保留交接內容。
- 合成 24 文件驗證不掃外部程式 repo、不呼叫外部工具。S4 以交接單加 roadmap 驗證空工作、失敗及下一步，另以實際未定版文件案例驗交付狀態。這是機械式接手驗收，**不是 E11 全新 agent 實測**。

## 3. 獨立審查與故意改錯

獨立審查另找到五個 P2，均已重現、補測、修復：無 delta 跳過使用者驗收、無 delta 用 analysis 替代 test、壞文章 store 誤報交接 current、Windows 相對路徑、巢狀能力影響追蹤。複核 **23 passed、55 deselected**；另驗正常無 delta 程式修正及有效豁免仍可封存，原五項無遺留。

在四份獨立暫存副本故意還原錯誤行為，沒有改動原工作區或測試：

- 移除必要測試到任務的連結檢查及封存證據檢查 → 未執行 T2 的測試在封存斷言失敗。兩處是同一完成條件的不同入口，不能只移除其中一處便宣稱已還原漏洞。
- 先濾掉未完整收集的執行再挑最新 → 逾時後錯用舊成功，回歸失敗。
- 忽略豁免裁定當前狀態 → 駁回後仍 done-waived，回歸失敗。
- 以曾定版代替目前內容已定版 → 修改文件後誤報 done，回歸失敗。

同批四例未改錯的副本先 **4 passed**；四個改錯副本各自 **1 failed**，均為預期的行為斷言失敗，無 setup／匯入錯誤。測試能抓到這四種錯誤，不代表能抓到所有未知錯誤。
