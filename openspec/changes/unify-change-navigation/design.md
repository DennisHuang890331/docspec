## Context

使用者否決把文件流程硬套軟體四件套。採共用資料夾及查詢；管理根目錄仍是 docspec。舊 software/changes 相容並保留封條與歷史。

## Goals / Non-Goals

統一發現與查詢，確保查詢唯讀及身分唯一。避免重設領域格式、驗收、文件開工時機與原建立入口；不支援並行寫入。

## Decisions

1. 用 change.yaml／proposal.yaml 識別領域，共用名字包含歷史；損壞與重複報錯。
2. 新軟體寫入共用根目錄，既有來源就地更新；明確遷移才搬動，先全部檢查後逐筆 rename，失敗逆向回復。
3. 查詢直接使用領域引擎，不透過會刷新任務的 CLI；歷史只讀保存紀錄。JSON／文字用同一結果。
4. 乾跑在記憶體重用任務推導，實際封存交易保存結果及原內容回復。

## Risks / Trade-offs

新舊兩位置需要同名檢查；共用根目錄不可讓文件掃描誤讀軟體，或失去 sealed 紀錄防護。遷移改路徑會讓交接 manifest 過時，這是實際變動，保留提示。既有基線全文不隨遷移改寫。

## Migration Plan

先查詢，再 migrate --dry-run，最後明確 migrate。舊資料可保持原位，查詢不替使用者選重複副本。
